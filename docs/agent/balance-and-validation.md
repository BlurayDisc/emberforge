# Balance (no unit tests)

- **Do not write unit tests.** Do not add a test framework or coverage tools. This is a personal game. Use tools instead: the balance simulator, the data validator and the smoke play script. When you add a command or a rule, add a step to `tools/smoke-play.ts`.
- Battles run in the real-time simulator (`simulateRealtimeBattle`, `src/systems/battle/realtime/`; numbers in `data/balance/battlefield.json`). Every scenario of `tools/balance-sim/` and the game itself use it. `npm run check:realtime` (part of `npm run check`) runs about 300 battles and checks blocking, range, speed and determinism.
- Balance is checked by `tools/balance-sim/`. It runs many seeded battles for each dungeon, with and without crafted gear. It prints win rate, duration (against the target curve in design.md section 8) and HP lost.
- Run `npm run balance` after you change stats, formulas, items, affixes, monsters or XP numbers. Fix the numbers in `data/balance/`, then run it again.
- `tools/validate-data.ts` checks the JSON in `data/`. It fails on:
  - a monster drop whose material tier differs from the tier of the dungeon bracket (the bracket rule),
  - a base item that needs a material category that a tier does not have (so a recipe would mix tiers or fail),
  - a dungeon level outside its town bracket,
  - an unknown id or sprite key.
  Run `npm run validate` after you edit `data/`.
- The combat model is flat (see design.md sections 4 and 8): armour takes points off a hit and a hit never does less than 1. Numbers live in `classes.json` (attributes and base values, with `balanceStatus` baseline or placeholder), `balance/hero-stats.json`, `balance/battle.json` (crit, minimum attack speed factor) and `balance/monster-scaling.json` (anchors per level). A normal or rare monster has `statFactor` and `attackSeconds`. A boss has `flatStats` (HP, damage, armour, Resistance, attack seconds) instead of a factor.
- `tools/validate-combat-model.ts` (called by the validator) checks the attribute budget (start total and gain total within 15% of the baseline classes), the class base values, the fixed resource pools, the monster anchors, the cast times and the boss: its four stats must sit on one common factor of the normal curve at its dungeon level, within 15%. Change a boss stat and the curve together, never one side alone. A removed old-model key in `balance/battle.json` fails the check.
- `tools/validate-gear-budget.ts` (called by the validator) checks the gear budget: whole number base stats, armour Defence of at least 2 with Heavy above Medium and Medium at or above Light, weapon damage within 1 of the rule in `weaponDamage` in `balance/items.json` (section 14 of the combat spec), a valid `mainStat`, and a useful stat on every craftable item.
- Every monster attack time must be inside 1.0 to 2.0 s (`minimumAttackSeconds` and `maximumAttackSeconds` in `balance/monster-scaling.json`, checked by `validate-combat-model.ts`). Boots give `movementSpeed` (percent, unscaled) and no attack speed. The smoke play (`tools/smoke-realtime-steps.ts`) checks that a planned encounter carries the real-time report, that one seed repeats, that boots reach the unit and that every monster attack time is in range.
- Never put an em dash in `data/` files. Use a normal hyphen - instead.

- `npm run scenarios -- first-fight` (preset `tools/balance-sim/presets/first-fight.json`) measures the first fight of each class against a same-level normal monster: HP lost, kill time and win rate, with gear states from the preset (main hand weapon only at level 1, Common gear above, and crafted Magic gear). Tune the monster anchors in `monster-scaling.json` against it.
- `npm run scenarios -- boss-fight` (preset `tools/balance-sim/presets/boss-fight.json`) runs the boss with four gear states: gear floor (target about 60% win), normal crafted gear (about 85%), weapon only (under 30%) and one hero without gear (0%). Each state has its own win rate range in the preset. The fight length target is about 30 s (soft; the real-time fight is about 18 s). The boss is one common factor of the level 10 curve (about x1.2 now): tune the factor of all four stats together and the numbers of its spells in `monster-spells.json`, never one stat alone.
